# SCOPE — 项目范围

## 定位

**ThreeJsRoomEditor** 是一个浏览器端、AI 原生的房间关卡编辑器，服务于
**ENTER THE CUBE**：36 个可互换的独立房间按 seed 拼装成一个巨大立方体，
外圈房间会整块塌落。房间形态是**很高的仓库 / loft**：外壳为全封闭立方体、
带固定数量的传送门，内部靠夹层平台与室内楼梯组织竖向空间。

运行时目标是 **UE 5.8.1**。本编辑器不是运行时，是**授权与生成工具**。

## 为什么不用 UE 编辑器

1. **太重** —— 摆几个盒子房间不需要开一个完整的 DCC
2. **对 LLM 不友好** —— `.umap` 是二进制，AI 无法读写，diff 无意义

本项目的存在理由就是这两条。任何让编辑器变重、或让数据变得不可被 LLM 读写的
改动，都在违背项目前提。

## 五条设计原则

### P1. 文档即真相

关卡是一份小而语义化的 YAML。存**意图**，不存推导结果。

推论（v0.2 起）：**能派生的一律不写进文档。** 房间尺寸、层高、传送门的数量与位置
全部由一个 `spec` 字段（S/M/L）派生 —— 见 `packages/schema/src/spec.ts`。
不是为了省字数，而是因为 36 个房间必须可互换：同规格房间的外形与接口一旦漂移，
拼装后就会门对上实墙。把它变成派生量，这类 bug 在结构上不可能发生，
**连校验规则都不需要**。

**硬指标：36 房间的房间库 < 1500 行、< 20k tokens，可整份进 LLM 上下文。**

### P2. 一个房间 = 一个独立关卡 ⭐

游戏是 **ENTER THE CUBE**：36 个房间是**可互换的独立单元**，每局按 seed
随机拼装成一个巨大立方体，外圈房间还会整块塌落。房间之间**没有固定连接** ——
运行时靠**传送门**跳转，去向由生成器决定，关卡作者不指定。

因此编辑器一次只编辑/显示**一个房间**，房间固定在原点。
把整份文档当成一个连通空间来摆位是错的模型。

文档里若有多个房间，视为一个**房间库**（36 个房间可以放在一起管理），
用房间选择器切换，彼此不产生几何关系。

房间朝向与出口编号由游戏侧处理（房间可旋转），编辑器只关心**布局与结构**。

> 早期版本把连接图 + 布局求解器当作核心（P2 原为「图驱动布局」）。
> 那是基于"关卡是连通空间"的误解。v0.2 已**删除**求解器、文档级 `connections`
> 与相关的 13 条校验规则 —— 房间永远在原点，没有可求解的东西。

### P3. 单一命令层

UI、AI agent、CLI、测试全部通过同一套 typed command 修改文档。禁止任何地方直接
mutate。免费获得 undo/redo、回放、确定性、审计日志，以及**人与 AI 能力对等**。

### P4. AI 输出命令，不输出代码

外部 agent 产出的是文档编辑或命令 JSON，经 schema 校验后应用。
**永不执行 LLM 生成的任意代码。**

### P5. 约束优先

材质 / 主题 / 道具 / 灯光全部走白名单预设库，不允许自由 shader。
**源头能表达的必须落在 UE 侧能自动重建的范围内**，否则导出必然失真。

## v1 范围内

### 房间模型

| 概念        | 说明                                                                                                                                          |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `Room`      | 轴对齐立方体外壳，**全封闭**。唯一的尺寸来源是 `spec`                                                                                         |
| `spec`      | `S`(1×1格) / `M`(2×1) / `L`(2×2)。派生净内空、层高、传送门                                                                                    |
| 传送门      | **派生**：每条占格边一个，居中于格边，恒 3.0 × 3.2m、贴地。作者无可调项                                                                       |
| `Opening`   | 手写的**非传送门**开口：`window`（造型用）等，带 `offset` + `size` + `elevation`                                                              |
| `Structure` | 内部结构件，**带碰撞与导航语义**：`platform`（= 夹层）/ `stair` / `ladder` / `ramp` / `catwalk` / `railing` / `pillar` / `beam` / `partition` |
| `Prop`      | 预设库道具实例（无导航语义）                                                                                                                  |
| `Light`     | 预设驱动光源：`point` / `spot` / `area` / `ambient`                                                                                           |
| `Marker`    | gameplay 标记：`spawn` / `trigger` / `objective` / `nav_hint` / `cover` / `item`                                                              |
| `Theme`     | 材质 + 灯光预设集合                                                                                                                           |

### 规格派生表（`packages/schema/src/spec.ts`）

格位 `GRID_UNIT = 30m`，墙厚 `WALL_T = 0.75m` 建在占格内侧。

| spec | 占格  | 外廓    | 净内空      | 层高 | 传送门               |
| ---- | ----- | ------- | ----------- | ---- | -------------------- |
| `S`  | 1 × 1 | 30 × 30 | 28.5 × 28.5 | 12   | 4（每面 1）          |
| `M`  | 2 × 1 | 60 × 30 | 58.5 × 28.5 | 18   | 6（宽墙 2 / 窄墙 1） |
| `L`  | 2 × 2 | 60 × 60 | 58.5 × 58.5 | 24   | 8（每面 2）          |

两条不变量，都有测试钉死：

1. **外廓 AABB 恒等于占格尺寸**（30/60m 的整数倍）→ 任意两房无缝对接
2. **传送门锚定在占格边中心**（offset 与墙厚无关）→ 拼装后必然对齐

M 房间在地图生成时允许竖放（60×30 或 30×60），那是游戏侧的旋转，
编辑器永远按标准朝向（长边沿 X）编辑。

### 编辑器

- 3D 视口（`WebGPURenderer`，自动 WebGL2 回退）：orbit / fly、gizmo、grid snap
- 房间选择器（多房间文档 = 房间库）+ 中英文界面切换
- Inspector：**schema 驱动自动生成**
- **文本模式**：直接编辑 YAML，与 3D 双向实时同步
- **write-through + file watcher 热重载**：外部 agent 改文件，浏览器立即更新
- 校验面板、undo/redo
- **第一人称漫游预览**（验证尺度感与串联流程）

### 导出

- 原生 `.roomgraph.yaml`
- glTF 场景
- UE 5.8.1 导入包（Phase 5）

## v1 明确不做

> 每次 PR review 对照本清单，防止蔓延成"再造一个更差的 UE 编辑器"。

- ❌ 非盒体房间（L 形、曲面、斜屋顶、地形）
- ❌ **自定义房间尺寸** —— 只有 S/M/L 三种规格，这是可互换性的前提
- ❌ **自定义传送门**（位置 / 数量 / 尺寸 / 数量都由 spec 决定）
- ❌ **多楼层关卡拓扑**（层高很高，但只有一个地面；竖向靠结构件）
- ❌ 房间的世界坐标、朝向、出口编号（都归游戏侧）
- ❌ 任意角度旋转
- ❌ 自由 shader / 材质图编辑
- ❌ 骨骼动画、角色、AI 行为
- ❌ 光照烘焙（Phase 5 交给 UE GPU Lightmass）
- ❌ 多人协同编辑
- ❌ UE → 编辑器 反向回写
- ❌ 完整 gameplay 模拟

## 性能目标

编辑器一次只渲染**一个房间**，所以性能上限由单房间复杂度决定，而不是房间数。
L 规格（60×60×24m）+ 密集结构件是当前的压力上限。
